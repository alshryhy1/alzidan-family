هذه الوثيقة هي **هوية المنتج اللغوية**. كل نص يظهر للزائر أو المندوب أو الإدارة يُراجع هنا قبل الشحن.

## 1) مبدأ Human First

كل ما يراه المستخدم يجب أن يكون **فعلًا بشريًا**، لا مصطلح قاعدة بيانات.

| بدلًا من (تقني) | يصبح (إنساني) |
|------------------|----------------|
| بطاقة الشجرة / Tree Card | أضف فردًا للعائلة |
| تعديل الشجرة | صحح بيانات شخص |
| بطاقة مناسبة / event_card | أعلن مناسبة |
| من الذاكرة / memory_card | شارك ذكرى |
| إنشاء طلب | ابدأ الآن |
| طلبات تعديل الشجرة | طلبات تحتاج مراجعتك |

داخليًا يبقى: `request_type` · `tree_card` · `REQ-…` للتشخيص والسجلات.  
**العرض للمستخدم:** أفعال عربية فقط.

## 2) قاعدة الثلاث لغات

كل عملية / حالة لها **ثلاث صيغ** — لا تُناقش أسماء الأزرار شاشةً بشاشة.

| التقنية (كود / DB / logs) | النظام (تقارير داخلية · تشغيل) | المستخدم (واجهات الزائر/المندوب/الإدارة) |
|---------------------------|--------------------------------|------------------------------------------|
| `tree_card` | إضافة فرد | أضف فردًا للعائلة |
| `tree_edit` | تصحيح بيانات | صحح بيانات شخص |
| `event_death` | إعلان وفاة | أعلن وفاة |
| `event_marriage` | إعلان زواج | أعلن زواج |
| `memory_card` | إضافة ذكرى | شارك ذكرى |
| `special_card` | طلب بطاقة | اطلب بطاقة |
| `delegate_secret_reset` | إعادة تعيين سر المندوب | طلب إعادة تعيين الرقم السري |
| `submitted` | مُقدَّم | تم الإرسال |
| `assigned` | مُعيَّن | وصل للمندوب |
| `in_review` | قيد المراجعة | تحت المراجعة |
| `needs_changes` | يحتاج تعديل | نحتاج معلومة إضافية منك |
| `approved` | تمت الموافقة | تم قبول طلبك |
| `applied` | طُبّق | تمت إضافة البيانات |
| `done` | مكتمل | اكتمل |
| `rejected` | مرفوض | لم يُقبل |

- عمود **التقنية** لا يظهر للمستخدم أبدًا.
- عمود **النظام** للوحة التشغيل الداخلية والتقارير.
- عمود **المستخدم** للواجهات الثلاث (صياغة قد تختلف قليلًا حسب الدور — انظر §4).

عند إضافة نية جديدة: حدّث أولًا [`REQUEST-CATALOG.md`](./REQUEST-CATALOG.md) ثم أضف الصف هنا.

## 3) مصطلحات محظورة في الواجهة (Forbidden UI Terms)

يُمنع ظهور أي من التالي في نص موجَّه للمستخدم النهائي (زائر · مندوب · مدير كمشغّل يومي):

| محظور | سبب |
|--------|-----|
| `JSON` | تفكير قاعدة بيانات |
| `Parent` / `parent_id` / `parent_person_id` | مصطلح تقني |
| `Branch` / `branch_key` خامًا كحقل يملؤه المستخدم | النظام يبني الفرع |
| `Lineage` / `Ancestors` | ليس لغة المستخدم |
| `tree_card` / `event_card` / `memory_card` / `special_card` كعنوان شاشة | استخدم الأفعال |
| `request_id` / `REQ-xxxx` كعنوان وحيد | يُعرض كعملية بشرية؛ المعرّف ثانوي/تشخيص |
| Nested form بلغة الجداول (الأب · المسار · الجد · … دفعة واحدة) | يخالف No Database Thinking |

**مراجعة شاشة جديدة:** هل تجعل المستخدم يفكر مثل قاعدة البيانات؟ إن نعم → إعادة صياغة قبل الدمج.

## 4) صياغة حسب الدور

نفس الحالة / نفس النية — نصوص مختلفة حسب الجمهور.

### الزائر (Visitor)

| السياق | صياغة مفضّلة |
|--------|---------------|
| بدء عملية | **ابدأ الآن** — ليس «إنشاء طلب» |
| اختيار النية | **ماذا تريد أن تفعل؟** — ليس «اختر نوع البطاقة» |
| عرض العملية | فعل + اسم بشري + حالة مفهومة (مثال: إضافة ابن · محمد بن حبيب · بانتظار المراجعة) |
| تتبع | مسار شحن: تم الإرسال → وصل للمندوب → تحت المراجعة → … |
| يحتاج تعديل | سبب واضح + **تعديل** + **إعادة الإرسال** |

في الخلفية فقط تتحول العملية إلى Request داخل Workflow.

### المندوب (Delegate)

| السياق | صياغة مفضّلة |
|--------|---------------|
| الطابور | **طلبات تحتاج مراجعتك** |
| السؤال المحوري | **ماذا يجب أن أنجز الآن؟** |
| بطاقة العمل | نفس النية البشرية + من أرسل + الحالة |

### الإدارة (Admin)

| السياق | صياغة مفضّلة |
|--------|---------------|
| القائمة | **إضافة فرد** · الاسم · المرسل · الحالة — ليس Tree Card / JSON أولًا |
| التفاصيل | عند الفتح: التفاصيل التقنية مخفية خلف طبقة ثانية إن لزم التشخيص |
| الدور | مراقبة **التدفق** — كم؟ أين تعطل؟ من يحتاج تدخلًا؟ — لا مراجعة أشخاص كلغة أساسية |

## 5) الرسائل والحالات (Messages & States)

| رمز المحرك | رسالة المستخدم (افتراضي) | ملاحظات |
|------------|---------------------------|---------|
| `submitted` | تم الإرسال | |
| `assigned` | وصل للمندوب | |
| `in_review` | تحت المراجعة | |
| `needs_changes` | نحتاج معلومة إضافية منك | إلزامي: سبب مقروء |
| `approved` | تم قبول طلبك | ليس نجاحًا نهائيًا بلا تطبيق (ADR-006) |
| `applied` | تمت إضافة البيانات | |

| `rejected` | لم يُقبل | مع سبب |

الإشعارات تُبنى من **انتقال الحالة** (انظر مواصفة السير) وتستخدم عمود المستخدم أعلاه.

## 6) قواعد الصياغة السريعة

1. فعل أمر أو جملة نية قصيرة في العناوين والأزرار.
2. اسم الشخص / الموضوع قبل المعرّف التقني.
3. لا تُظهر حقول النظام التي يبنيها المحرك تلقائيًا.
4. عند الشك: راجع [`PLATFORM-PRINCIPLES.md`](./PLATFORM-PRINCIPLES.md) (Human First · No Database Thinking · ثلاث لغات).
