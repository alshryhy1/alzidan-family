## 1) أدلة من صفحة المندوب الحالية (لقطة المستخدم)

المستخدم لصق/عرض صفحة المندوب الحالية (`pages/alzidan-tree.html` + `delegate.js`). الخلاصة الثابتة:

- الصفحة ما زالت **إدارة شجرة أولاً (tree-first admin)** وليست مساحة عمل طلبات.
- يظهر «لوحة فرع…» و«إدارة العائلة: اختر شخصاً…» — نقطة الدخول = **شخص** لا **طلب**.
- Person hub: زوجات / أبناء / إضافة / تعديل / حذف — محرّر عائلي إداري الشعور.
- نماذج مناسبات وذكريات كأقسام منزل موازية للفرع — ليست أدوات داخل جلسة طلب.
- **لا** صندوق وارد طلبات-أولاً · **لا** جلسة عمل لكل طلب · **لا** «الطلب التالي».
- الكتابة على الشجرة تتم غالبًا **مباشرة من واجهة المندوب** (مثل `tree_children` / الزوجات) خارج مسار Workflow + Validation الكامل.
- هذا يناقض السؤال المحوري المعتمد للمندوب: «ماذا يجب أن أنجز الآن؟» ([`DELEGATE-WORKSPACE-UX-v1.md`](./DELEGATE-WORKSPACE-UX-v1.md)).
- **الخلاصة:** لا تُختبر/تُراجع صفحة المندوب بمعزل؛ أي إعادة تصميم للمندوب تنتظر RX→VE→WF.

## 2) خارطة الرحلة الحالية (As-Is)

```
┌─────────────────────────────────────────────────────────────────────────┐
│  الزائر — الصفحة الرئيسية (index)                                       │
│  «إضافة بيانات للشجرة» · نموذج بطاقة (جد/أب/اسم…) · «إرسال البطاقة»   │
│  «إضافة مناسبة» (زواج/مولود/…) · ذكرى / بطاقات عبر مسارات منفصلة      │
└───────────────────────────────┬─────────────────────────────────────────┘
                                │ insert → approval_requests
                                │ kind ≈ tree_card / event_* / memory_* …
                                ▼
┌─────────────────────────────────────────────────────────────────────────┐
│  الإدارة — موديول الطلبات (+ لوحة Workflow provisional إن فُعّل SQL)     │
│  مراجعة · قبول/رفض (مسار قديم status) · أحيانًا انتقال wf_*             │
│  أثر الشجرة: apply متحقَّق جزئيًا (Patch 2+) — ليس كل الأنواع موحّدًا   │
└───────────────┬─────────────────────────────┬───────────────────────────┘
                │                             │
                │ مسار اعتماد/تطبيق           │ مسار موازٍ شائع اليوم
                ▼                             ▼
┌───────────────────────────┐   ┌─────────────────────────────────────────┐
│ Workflow Engine v1        │   │ المندوب — alzidan-tree (legacy)         │
│ provisional على main      │   │ لوحة فرع · اختر شخصًا · زوجات/أبناء     │
│ تعيين/انتقال غير مكتمل    │   │ مناسبات · ذكريات كأقسام منزل            │
│ Stub مندوب: غير جاهز      │   │ كتابة مباشرة على الشجرة/الخدمات         │
└───────────────────────────┘   └──────────────────┬──────────────────────┘
                                                   │
                                                   ▼
                                    Family Engine / tree_* / events / memory
                                    (أثر قد يصل بلا جلسة طلب واضحة)
```

### 2.1 تفصيل الأسطح (كما هي اليوم)

| السطح | ماذا يحدث فعليًا |
|--------|------------------|
| **الرئيسية** | نماذج منفصلة بلغة «بطاقة / مناسبة»؛ حقول نسب متداخلة (جد ١…٤ · أب · اسم) — تفكير شجرة/DB أكثر من نية بشرية واحدة. الإرسال → `approval_requests`. تتبع إنساني للزائر ضعيف/غير موحّد. |
| **أنواع الطلب** | فهرس الدستور موجود؛ الواجهة ما زالت تسمّي «بطاقة الشجرة» وغيرها. مسارات متعددة (شجرة · مناسبة · ذكرى · مندوب · سر) بلا تجربة نية موحّدة. |
| **الإدارة** | قائمة طلبات + أزرار قبول/رفض/إعادة تطبيق؛ لوحة Workflow مصغّرة (قراءة/انتقال إداري) إن طُبّق SQL. الدور اليوم = **مراجع طلبات + مشغّل** أكثر من **مراقب تدفق**. |
| **Workflow / legacy** | أساس v1 provisional؛ `status` القديمي ما زال حيًا؛ مسار اعتماد قديم لم يُزل؛ انتقال المندوب عبر المحرك غير جاهز (`WF-DELEGATE-NOT-READY`). |
| **صفحة المندوب** | tree-first: بعد الدخول → لوحة فرع + Family Management (اختر شخصًا) + مناسبات + ذكريات. **ليست** Inbox طلبات. |
| **أثر الشجرة** | (أ) apply من الإدارة لبعض `tree_card`؛ (ب) كتابة مباشرة من المندوب للأبناء/الزوجات/التعديل؛ (ج) مناسبات/ذكريات عبر لوحات المندوب. خطر خلط وصعوبة Audit موحّد. |

### 2.2 نقاط الألم ومخاطر الشجرة

| لحظة | الألم / الخطر |
|------|----------------|
| **إضافة شخص** | من الرئيسية: نسب بالأسماء قد يلتبس؛ من المندوب: إضافة مباشرة دون جلسة طلب/تحقق مركزي → تكرار · أب خاطئ · ترتيب ميلاد متعارض. |
| **تعديل بيانات** | مسارات متفرقة (طلب تصحيح · محرّر شخص في المندوب · إدارة) — بلا مقارنة «المسجّل الآن vs المقترح» كقاعدة منتج. |
| **إضافة زوجات** | كتابة من واجهة المندوب؛ خطر ربط بزوج خاطئ أو تجاوز صلاحية/طلب. |
| **ميلاد / وفاة** | مناسبة من الرئيسية vs محرّر أحداث المندوب vs تواريخ على بطاقة الشخص — DateEngine غير معمَّم على كل النماذج (TD-1). |
| **مناسبات** | ازدواج: طلب مراجعة + إدارة مباشرة في لوحة المندوب — الزائر/المندوب/الإدارة لا يشتركون بنفس عُقد الحالة دائمًا. |
| **خلط الأدوار** | المندوب يعمل كـ mini-admin للفرع؛ الإدارة تعتمد وتطبّق؛ لا طابور مهام واضح → أخطاء بشرية على بيانات حساسة. |
| **Single Write Rule** | غير مُطبَّق بالكامل — واجهات تكتب على الشجرة خارج Workflow + Validation. |
| **Truth Before Speed** | لا Validation Engine مستقل قبل وصول الطلب للمندوب/الشجرة. |

## 3) الرحلة المستهدفة (To-Be) — وحدة واحدة

ترتيب السلّم المعتمد (لا يُعاد ترتيبه):

```
Request Experience → Validation Engine → Workflow Engine
        → Delegate Workspace → Admin (مراقبة)
```

بلغة المنتج (نية أولاً):

```
زائر: ماذا تريد أن تفعل؟          ← Request Experience
        ↓ حقائق قصيرة
Validation: هل الحقائق سليمة؟     ← يتحقق ولا ينفّذ
        ↓
Workflow: إنشاء · تعيين · حالة · Audit · إشعار
        ↓
مندوب: ماذا يجب أن أنجز الآن؟     ← Inbox → جلسة طلب → قرار → التالي
        ↓ approved → applied (متحقَّق)
Family Engine / الخدمات            ← كتابة واحدة فقط
        ↓
إدارة: أين التدفق؟ أين الاختناق؟  ← مراقبة · تدخل استثنائي
        ↓
أثر ظاهر للزائر + سجل للإدارة
```

### 3.1 كيف تُبسَّط الرحلة (نفس الطلب من البداية للنهاية)

1. **الرئيسية:** اختيار نية من [`REQUEST-CATALOG.md`](./REQUEST-CATALOG.md) بلغة بشرية («أضف فردًا» لا «بطاقة شجرة») + حقول حقائق قليلة؛ النظام يبني الربط.
2. **Validation:** قبل التعيين/الشجرة — هوية · تكرار · تعارض · اكتمال · أسباب واضحة.
3. **Workflow:** حالة ومالك واحد في كل لحظة؛ إشعار من الانتقال لا من الزر.
4. **المندوب:** طابور «طلبات تحتاج مراجعتك» → جلسة واحدة لكل طلب → أدوات سياق عند الحاجة فقط → قبول / نحتاج معلومة / رفض → **الطلب التالي** تلقائيًا.
5. **الإدارة:** تراقب التدفق والحمل والتأخير؛ لا تكون لغة اليوم «راجع الشخص في الشجرة» كمسار أساسي.
6. **الشجرة:** تُمسّ فقط بعد اعتماد متحقَّق عبر المحرك + الخدمة — لا محرّر فرع كممر يومي لإضافة أفراد الفهرس.

## 4) دور كل سطح — جملة واحدة

| السطح | الدور (جملة واحدة) |
|--------|------------------|
| **الصفحة الرئيسية / الزائر** | يجمع نية الزائر وحقائقه القصيرة ويتابع حالته بلغة بشرية — دون بناء الشجرة. |
| **الإدارة (Admin UX)** | تراقب تدفق الطلبات والاختناقات وتتدخل استثنائيًا — لا محرّر أشخاص كلغة أساسية. |
| **Workflow Engine** | مصدر الحقيقة لحالة الطلب والتعيين والانتقال والسجل والإشعار — بلا شكل شاشة. |
| **Validation Engine** | يفحص الحقائق والتعارضات قبل المندوب أو طفرة الشجرة — يتحقق ولا ينفّذ. |
| **Delegate Workspace** | ينجز المندوب الطلب كجلسة عمل من الطابور إلى القرار ثم الطلب التالي — الشجرة أداة داخل الجلسة فقط. |

## 6) فجوات — ما يكسر سلامة الشجرة اليوم · وما تملكه كل مرحلة لاحقًا

### 6.1 ما يكسر / يهدد سلامة الشجرة اليوم

1. **كتابة مباشرة من واجهة المندوب** على الأبناء/الزوجات/التعديل خارج Single Write Rule.  
2. **غياب Validation Engine** قبل القبول أو قبل الكتابة — تعارضات تظهر متأخرًا أو كأخطاء SQL خام.  
3. **ازدواج مسار الاعتماد:** `status` قديم + `wf_*` provisional + apply إداري — سهولة REQ-001 (قبول بلا أثر) أو أثر بلا سياق طلب.  
4. **ربط/إدخال بالأسماء** في نماذج الزائر والحالات الحدّية — خطر أب/شخص خاطئ عند غياب `person_id`.  
5. **محرّر شخص + حذف** ظاهر في سياق المندوب — سطح خطأ عالٍ على بيانات نسب.  
6. **تواريخ الميلاد/الوفاة/المناسبات** غير موحّدة بالكامل عبر DateEngine.  
7. **لا جلسة طلب** للمندوب → قرارات بلا مقارنة حقائق وبلا أثر رجوع منظّم للإدارة/الزائر.  
8. **لغة «بطاقة / اختر شخصًا»** تدفع المستخدم للتفكير كقاعدة بيانات لا كنية.

### 6.2 ملكية المراحل القادمة (ماذا تملك كل مرحلة)

| المرحلة | تملك | لا تملك / لا تبدأ الآن |
|---------|------|-------------------------|
| **بوابة 1 — Delegates v2** | صلاحية · دور · فرع · تفعيل · Audit صلاحيات (قبول حي) | تجربة الطلب · UI مندوب جديد |
| **بوابة 2 — Foundation** | تجميد الدستور الحي + Truth Before Speed | كود منتج جديد خارج التجميد |
| **Request Experience** | نية موحّدة · نماذج قصيرة · تتبع إنساني من الرئيسية | منطق تحقق/حالات · كتابة شجرة |
| **Validation Engine** | هوية · تكرار · تعارض · اكتمال · أسباب قبل الشجرة/المندوب | التنفيذ البشري · آلة الحالات |
| **Workflow Engine (إغلاق)** | انتقالات · تعيين · إزالة مسار قديم · إشعار من الحالة · استقرار | تصميم شاشات RX/DW |
| **Delegate Workspace** | Inbox · جلسة · أدوات سياق · قرار · التالي | مراقبة تدفق Admin · بناء نية الزائر |
| **Admin UX** | لوحة تدفق · تأخير · حمل · تدخل استثنائي | أن تكون منزل تنفيذ المندوب |
| **Family Engine Alignment** | Single Write Rule · عقود خدمات · منع UI→شجرة لعمليات الفهرس | إعادة بناء الشجرة من الصفر |
