# Person Visibility Specification v1

**الحالة:** ✅ **معتمد من صاحب المنتج** · 2026-08-15  
**عبارة الاعتماد:** «اعتمدوا Person Visibility Specification» (بعد تثبيت ترتيب Viewer→Visibility)  
**النوع:** مواصفة منتج/معمارية فقط · **ممنوع التنفيذ كود** حتى قرار منفصل  
**يعتمد على:**  
GEN-01 ✅ · LIVE Media Audit ✅ · `ARCHITECTURE-AUDIT-PREP` · الوجود ≠ الظهور  
**لا يشمل:** Person Photo · Media Migration · DW · كود UI · Composition→تنفيذ

---

## 1) الغرض

تحديد **من يصل إلى واجهة «شخص» وأي سطح عام** قبل تصميم لقاء الشخص.

> البيانات كاملة في Family Graph.  
> الظهور قرار سياسة + سياق مشاهد — **لا** مكان الجدول، **لا** الجنس وحده، **لا** إخفاء بعد `SELECT *`.

المسار الإلزامي:

```text
DB / Family Graph
        ↓
Viewer Context / Identity   ← من يشاهد؟ (زائر · عضو · self_access …)
        ↓
Visibility Resolver         ← ماذا يُجلب لهذا المشاهد ولهذا السطح؟
        ↓
Capabilities                ← ماذا يُسمح له أن يفعل؟
        ↓
UI
```

**لماذا Identity قبل Visibility؟**  
بعض قرارات الظهور تعتمد على المشاهد (`kinship_surface` · `self_access` · زائر مقابل عضو).  
Visibility **ليست** خطوة عمياء قبل معرفة من يشاهد — مع بقاء الفصل المفاهيمي:

```text
Visibility ≠ Access ≠ Capabilities
```

## 2) مبادئ ملزمة

| # | المبدأ |
|---|--------|
| 1 | **الوجود ≠ الظهور** |
| 2 | **الوسيط ≠ هوية الشخص** (لا Avatar/Person Photo في هذه المواصفة) |
| 3 | **GEN-01:** ابنة وزوجة وأي فئة مستقبلية تحت **سياسة ظهور واحدة** — لا حذف/نقل جداول للإخفاء |
| 4 | مكان السجل (`tree_children` / `tree_spouses` / …) **لا** يحدد الظهور |
| 5 | **الجنس ≠ محرك ظهور** · صفة الذكورة ليست بذاتها قاعدة اكتشاف |
| 6 | الواجهات العامة الحالية **لا** تعرض العنصر النسائي في البحث/التسلسل/عائلة الشخص/النبض/المناسبات كسطح قرابة |
| 7 | المحرك يبقى قادرًا على النسب والقرابة داخليًا حتى لو عقدة غير ظاهرة للواجهة |
| 8 | تجربة نسائية مستقلة مستقبلًا = Experience + Access + Capabilities + Visibility Scope — **بدون** نسخ الشجرة |
| 9 | **`discoverable_public = false` لا يعني `can_login = false`** |
| 10 | **رقم الجوال ليس جزءًا من Discoverability** |
| 11 | **الظهور يحدده النظام** (هوية السجل · نوعه · سياسة الظهور · سياق المشاهد) — **ليس** مفتاح «ظاهر/غير ظاهر» يضبطه كل عضو لنفسه |
| 12 | **المرأة ≠ معنى «غير ظاهر»** · الجنس يدخل في تحديد **التجربة الحالية**، وليس محرك Visibility بحد ذاته |
| 13 | خيار خصوصية مستقبلي إن وُجد = محدود (مثل السماح بإظهار الجوال) · **ليس** «إخفاء حسابي بالكامل» كافتراض v1 |

## 3) ثلاثة طبقات منفصلة (أبعاد منطقية)

أسماء منطقية — ليست أعمدة مفروضة في هذه المرحلة.

### 3.1 Visibility — ماذا يُعرض / يُجلب لهذا السطح؟

| البُعد | المعنى |
|--------|--------|
| `exists_in_graph` | موجود في المحرك |
| `discoverable_public` | قابل للاكتشاف في البحث العام / دليل الأشخاص |
| `lineage_public` | يظهر في تسلسل/شجرة عامة |
| `kinship_surface` | يظهر في أسطح القرابة للعضو (غير الذات) |
| `engine_only` | للاستخدام الداخلي في النسب فقط (قد لا يُعرض أبدًا للعامة) |

### 3.2 Identity / Access — من هو المشاهد وما علاقتها بالسجل؟

| البُعد | المعنى |
|--------|--------|
| `account_eligible` | يمكن ربط حساب بهذا السجل مستقبلًا/حاليًا |
| `account_exists` | يوجد حساب مربوط فعليًا |
| `can_login` | يستطيع صاحب الحساب تسجيل الدخول |
| `self_access` | المشاهد هو صاحب هذا السجل — يرى تجربته الشخصية حتى لو غير قابل للاكتشاف عامًا |

### 3.3 Capabilities — ماذا يُسمح بفعله بعد الهوية؟

| البُعد | المعنى |
|--------|--------|
| `interact_eligible` | تفاعل مصرّح (تهنئة/تواصل… حسب السياسة) |
| `publish_eligible` | نشر محتوى عائلي مصرّح |
| `upload_eligible` | رفع وسائط مصرّح |
| `delegate_contact_eligible` | تواصل مع مندوب الفرع (لاحقًا مع DW) |

## 4) قاعدة الجلب (حاسمة)

> **أي بُعد Visibility = false يمنع جلب السجل لذلك السطح.**  
> **Access / Capabilities تُقيَّم بعد تحديد هوية المشاهد ولا تُستخدم كفلاتر اكتشاف عامة.**

### صحيح

```text
discoverable_public = false
        ↓
لا يُجلب في البحث العام / الدليل العام

account_exists = true · can_login = true · self_access = true
        ↓
تستطيع صاحبة الحساب الدخول لتجربتها المسموحة
```

### خاطئ

```text
discoverable_public = false  ⇒  can_login = false   ← ممنوع كاستنتاج
account_eligible = false     ⇒  لا تجلب الصف أبدًا  ← ممنوع كفلتر اكتشاف
interact_eligible = false    ⇒  احذف من البحث       ← ممنوع
```

## 5) Self Access — «الشخص يرى نفسه»

| السيناريو | النتيجة |
|-----------|---------|
| زائر / عضو آخر · الهدف غير قابل للاكتشاف العام | لا بحث · لا بطاقة عامة · لا تسلسل عام يكشف العقدة |
| **صاحب الحساب نفسه** (`self_access`) | يرى حسابه وتجربته الشخصية المسموحة **حتى لو** غير قابل للبحث/الشجرة العامة |

```text
Public viewer
  → Viewer Context → Visibility Resolver

Authenticated member viewing someone else
  → Viewer Context → Visibility + Capabilities على الهدف

Authenticated member viewing self
  → self_access + Access + Capabilities الخاصة به
  (لا تُلغى بسبب عدم الاكتشاف العام)
```

### 5.1 من يقرر الظهور؟ (محسوم)

**النظام** — لا شاشة «أنا أظهر/أخفي سجلي».

| الحالة | مثال | الظهور العام |
|--------|------|--------------|
| شخص ضمن الواجهة الحالية | محمد خميس | يظهر حسب سياسة الظهور + سياق المشاهد |
| عنصر نسائي (مسجل أو غير مسجل) | ابنة / زوجة | في DB والمحرك · **غير ظاهر في الواجهات العامة الحالية** |
| محجوب لسبب خصوصية | أي شخص مستقبلًا | لا يظهر للعامة (سياسة/قرار نظام أو إجراء محكوم — ليس زرًا حرًا في v1) |

«غير ظاهر» = غير قابل للاكتشاف/العرض على الأسطح العامة — **مع** بقاء الوجود في Graph وإمكانية الاستخدام في النسب و`self_access` لاحقًا.

### 5.2 `visibility_scope` داخلي (مستقبلي · منطقي)

قيم مرشّحة للمحرك (ليست UI للعضو):

`public` · `member` · `self` · `private` · `engine_only`

**ممنوع:** ربط مباشر `gender → visibility_scope` كقاعدة محرك.  
**مثال توضيحي فقط:** أنثى مسجلة قد تكون `member`/`self` · زوجة بلا حساب `engine_only` · ذكر طلب حجبًا محكومًا `private` — كلها عبر **نفس** Visibility Engine.

### 5.3 ممنوع تثبيته في Composition / واجهة المستخدم

| لا تُثبَّت | البديل / القاعدة |
|-----------|------------------|
| عنوان «سياسة الظهور» للمستخدم | ممنوع كعنوان واجهة |
| مفتاح أو جملة «ظاهر / غير ظاهر في البحث العام» على شاشة الحساب | **ممنوع افتراضيًا** · Visibility سياسة نظام صامتة · لا تُعرض إلا بقرار منتج صريح لحالة فعلية |
| افتراض أن كل حساب «غير ظاهر» | ممنوع · لا تخترع حالة Visibility في الـComposition |
| «تواصل مع محمد» دائم / شات | ممنوع |
| كتلة مساعدة مندوب + أنواع طلب داخل اللقاء | ممنوع كقسم ثابت · DW منفصل |
| «سجّل لترى المزيد» المزعج | ممنوع · إن لم يُسمح بعرض عنصر للزائر → **احذفه بصمت** · لا تكشف وجود مخفي |

**Visibility Specification = كيف يقرر النظام الظهور لاحقًا.**  
**ليست** إعدادًا في صفحة الحساب · **وليست** نصًا يجب أن يراه المستخدم عن حالته.

**التفاعل مع الشخص = سياقي فقط** (مناسبة/حالة الآن): هنّئ · بارك · عزِّ · ادعُ → ينتهي بانتهاء الحالة.

## 6) كيانات الهوية (Graph) — دون فرض الظهور

| كيان | أين يُخزَّن اليوم (As-Is) | ملاحظة |
|------|---------------------------|--------|
| ابن / ابنة | `tree_children` | الدور/الجنس يُحفظ لاحقًا **دون** ربطه بالظهور |
| زوج / زوجة | زوج في `tree_children` · زوجة في `tree_spouses` | هوية كاملة ممكنة مستقبلًا مع بقاء عدم الظهور العام |
| عضو | `member_profiles` ↔ شخص | الحساب ≠ قابلية الاكتشاف |
| سجل داخلي | طلبات / حالات داخلية | غير قابل للبحث العام |

**As-Is (Audit):** اليوم الابنة تظهر لأنها في `tree_children` بلا سياسة · الزوجة لا تظهر لأن الاستعلام لا يحمّلها — **ليس الحل**؛ الحل = Visibility Resolver عند التنفيذ.

## 7) المصفوفة المستهدفة (نوايا منتج)

### 7.1 المشاهدون

| المشاهد | التعريف |
|---------|---------|
| **زائر** | غير مسجّل — قد يكون من العائلة دون تحقق · لا يُوسم غريبًا |
| **عضو (يشاهد غيره)** | مسجّل · ليس وصولًا مطلقًا |
| **عضو (يشاهد نفسه)** | `self_access` |
| **محرك / إدارة / مندوب مخوّل** | خارج أسطح العائلة العامة |

### 7.2 كيانات × Visibility (لا Access)

| الحالة | exists | discoverable_public | lineage_public | kinship_surface | engine_only ممكن؟ |
|--------|-------:|--------------------:|---------------:|----------------:|------------------:|
| **شخص يمر بسياسة الظهور الحالية** (غالبًا ابن في الواجهات الحالية) | نعم | نعم | نعم | نعم | نادرًا |
| **ابنة** | نعم | **لا** (واجهات حالية) | **لا** | **لا** | نعم للنسب |
| **زوجة** | نعم | **لا** | **لا** | **لا** | نعم للنسب |
| **عضو/شخص غير قابل للاكتشاف** | نعم | **لا** | حسب السياسة | حسب السياسة | حسب الحاجة |
| **سجل داخلي** | نعم أو طلب | لا | لا | لا | نعم |

**صياغة ملزمة:**

> **الشخص الظاهر حاليًا = سجل يمر بسياسة الظهور الحالية لسياق المشاهد.**  
> **الجنس ليس Visibility Engine** (`gender = male → discoverable` **ممنوع**).  
> الواجهات العامة الحالية موجّهة لما تسمح به السياسة الآن (بما فيها عدم عرض العنصر النسائي على أسطح القرابة/البحث/التسلسل)، مع بقاء السجلات في Graph.

### 7.3 Access منفصل (أمثلة)

| الحالة | account_eligible | account_exists | can_login | self_access عند تسجيل الدخول |
|--------|-----------------:|---------------:|----------:|-----------------------------:|
| ابنة / زوجة مستقبلًا | نعم ممكن | إن وُجد حساب | إن وُجد حساب | نعم لتجربتها |
| عضو غير قابل للاكتشاف | نعم | نعم | نعم | نعم |
| سجل داخلي بلا حساب | لا / لاحقًا | لا | لا | لا |

### 7.4 عناصر «لقاء الشخص»

| العنصر | زائر | عضو يشاهد غيره | صاحب الحساب (`self_access`) |
|--------|------|----------------|------------------------------|
| الاسم | ✓ إن اكتُشف | ✓ إن سُمح | ✓ |
| الفرع | إن عام | ✓ | ✓ |
| الصلة الشخصية | ✕ عادةً | ✓ إن مثبتة | — (ذاته) |
| التسلسل | حسب ظهور عام؛ **بدون كشف عقد مخفية** | حسب سياسة؛ **بدون كشف عقد مخفية** | حسب تجربته |
| عائلته | ظاهرون فقط | ظاهرون فقط | حسب السياسة |
| مناسبة عامة | ✓ إن وُجدت | ✓ | ✓ |
| جمعتكما | ✕ | إن وُجدت | — |
| تواصل دائم مع الشخص | ✕ | ✕ | — |
| تفاعل سياقي (مناسبة/حالة الآن) | إن سمحت سياسة المناسبة للزائر | هنّئ / بارك / عزِّ / ادعُ إن وُجدت حالة | — |
| مساعدة مندوب / أنواع طلب | ✕ من شاشة اللقاء | ✕ قسم ثابت هنا | ✕ |
| **رقم الجوال** | **✕ دائمًا** | **✕ لمجرد العضوية** | إدارة ذاتية بلا أرقام للغير · بلا عرض حالة ظهور |
| **جملة ظهور حسابك / غير ظاهر** | ✕ | ✕ | **✕ افتراضيًا** (سياسة نظام صامتة) |
| سجّل لترى المزيد (مزعج) | ✕ احذف المخفي بصمت | — | — |
| صورة شخص | خارج v1 | خارج v1 | خارج v1 |
| مندوب / أنواع طلب | ✕ | ✕ قسم ثابت | ✕ |

**قاعدة الجوال:**

> رقم الجوال **ليس** جزءًا من Discoverability.  
> وجوده في DB أو استخدامه لتسجيل الدخول **لا** يجعله قابلًا للعرض في بطاقة الشخص.  
> عضو يشاهد شخصًا آخر **لا** يرى الجوال لمجرد أنه عضو.

أقسام بلا بيانات → **تُحذف** من الشجرة البصرية (لا فراغ زومبي).

## 8) المحرك يعرف أكثر مما تعرض الواجهة

إذا كان مسار القرابة:

```text
حسن → سليمان → [عقدة غير ظاهرة] → محمد
```

| الطبقة | السلوك |
|--------|--------|
| **المحرك** | قد يستخدم العقدة المخفية لحساب «ما صلتي بمحمد؟» / التسمية |
| **الواجهة** | **لا تكشف** اسم/بطاقة/حلقة للعقدة المخفية · تعرض نتيجة مسموحة (مثل «ابن خالك») أو مسارًا مُصفّى من الحلقات الظاهرة فقط |

> لا تفشل إجابة القرابة فقط لأن جزءًا من النسب داخلي وغير قابل للعرض.  
> ولا تُسرَّب العقدة المخفية عبر التسلسل المرئي.

## 9) قواعد الاستعلام (عند التنفيذ لاحقًا)

1. Surfaces العامة (بحث · شجرة · تسلسل عام · دليل) تُصفّى بـ **Visibility فقط**.  
2. بعد المصادقة: يُقيَّم `self_access` ثم Access ثم Capabilities — **منفصلة**.  
3. الزوجات والبنات لا يُحل ظهورهما بـ«لا تحمّل الجدول» كسياسة دائمة.  
4. ممنوع: `SELECT *` ثم إخفاء في UI.  
5. ممنوع: `gender = male → discoverable` كقاعدة محرك.  
6. ممنوع: ربط `discoverable_public=false` بمنع الدخول أو منع التجربة الذاتية.

*(مواصفة — لا تنفيذ الآن.)*
