## 1) الغرض والتموضع

### 1.1 ماذا هي Request Experience؟

واجهة الزائر (والمسار التشغيلي المخصّص لسر المندوب في الإدارة) تجيب عن سؤال واحد:

> **ماذا تريد أن تفعل؟**

الزائر يختار **نية بشرية** من الفهرس، يملأ **حقائق قصيرة**، يرسل، ثم **يتابع** حالته بلغة الشحن البشرية — دون بناء الشجرة ودون مصطلحات قاعدة بيانات.

### 1.2 ماذا ليست؟

| ليست | لأن |
|------|-----|
| محرّر شجرة / نسب متداخل | النظام يبني الربط — الزائر يقدّم حقائق |
| Validation Engine | RX تجمع وتعرض — لا تعيد اختراع فحوصات الأعمال |
| Workflow Engine | RX لا تملك الحالات ولا التعيين |
| Delegate Workspace | مساحة المندوب مرحلة لاحقة · UX منفصل معتمد |
| لوحة «اختر نوع البطاقة» | لغة محظورة — النية فعل بشري |
| توسعة فهرس مرشّح | زوجة/أبناء/ميلاد بلا صف فهرس = لا شاشة |

### 1.3 الطبقة في المعمارية

```
الزائر
   │
   ▼
Request Experience     ← نية · حقائق · تتبع إنساني
   │ يسلّم حقائق
   ▼
Validation Engine      ← يتحقق — لا ينفّذ
   │
   ▼
Workflow Engine        ← حالة · مالك · Audit · إشعار
   │
   ▼
(… مندوب / إدارة / خدمات عند applied)
```

**قاعدة الطبقة (أ):** كل عنصر في RX = طبقة Request Experience فقط.  
أي منطق تحقق أعمال أو انتقال حالة داخل الواجهة = **رفض تصميم**.

## 2) مبادئ التصميم (غير قابلة للتفاوض)

| # | المبدأ | المعنى في RX |
|---|--------|--------------|
| 1 | **Human First** | أفعال عربية من [`PRODUCT-LANGUAGE.md`](./PRODUCT-LANGUAGE.md) فقط |
| 2 | **نية أولًا** | الشاشة الأولى = «ماذا تريد أن تفعل؟» لا نموذج طويل |
| 3 | **نماذج قصيرة** | أقل حقول لازمة · الباقي يبنيه النظام / VE / المندوب |
| 4 | **No Database Thinking** | ممنوع: JSON · Parent · tree_card كعنوان · نسب جد١…٤ دفعة واحدة كلغة أساسية |
| 5 | **Single Write Rule** | RX لا تكتب على `tree_*` / أحداث معتمدة / memory / cards خارج مسار الطلب |
| 6 | **Truth Before Speed** | عند فشل VE: رسالة بشرية + تعديل — لا «إرسال رغم الخطأ» |
| 7 | **تسليم نظيف لـ VE** | حمولة حقائق + نوع الفهرس — بلا قرار اعتماد في الواجهة |
| 8 | **تتبع إنساني** | حالات الشحن من لغة المنتج — لا رموز WF خامًا للمستخدم |

## 3) نطاق النوايا — RX v1

### 3.1 معتمدة (من الفهرس فقط)

| نية العرض (الزائر) | النوع الداخلي | ملاحظات UX |
|--------------------|---------------|------------|
| أضف فردًا للعائلة | `tree_card` | حقائق الشخص + سياق الأب/الربط الذي يساعد النظام (بحث بشري لا حقل id) |
| صحح بيانات شخص | `tree_edit` | اختيار شخص موجود ثم الحقول المراد تصحيحها فقط |
| أعلن وفاة | `event_death` | شخص + تاريخ (+ سبب إن لزم السياسة) |
| أعلن زواج | `event_marriage` | الطرفان + تاريخ |
| شارك ذكرى | `memory_card` | نص/وسائط + روابط أشخاص اختيارية |
| اطلب بطاقة | `special_card` | نوع البطاقة + المستهدف + حقول النوع |

**نية تشغيلية (ليست كروم الرئيسية للزائر):**

| نية | أين | النوع |
|-----|-----|--------|
| طلب إعادة تعيين الرقم السري | شاشة إدارة مخصّصة | `delegate_secret_reset` |

### 3.2 خارج النطاق (⬛ مؤجّل — مرشّحات الرحلة)

لا بطاقة نية · لا مسار · لا نسخة تجريبية:

- أضف زوجة  
- أضف أبناء (كنية مستقلة)  
- أعلن ميلاد / مولود  
- «أعلن مناسبة» كآلة حالات جديدة  

عند حسم المنتج لاحقًا: صف فهرس → لغة المنتج → تحديث هذه المواصفة — ثم فقط.

## 4) هيكل التجربة (شاشات منطقية)

> شاشات منطقية — ليست أسماء ملفات ولا فرض إطار عمل.

### 4.1 الرئيسية — اختيار النية

```
┌──────────────────────────────────────────┐
│  ماذا تريد أن تفعل؟                      │
│                                          │
│  [ أضف فردًا للعائلة ]                   │
│  [ صحح بيانات شخص ]                      │
│  [ أعلن وفاة ]                           │
│  [ أعلن زواج ]                           │
│  [ شارك ذكرى ]                           │
│  [ اطلب بطاقة ]                          │
│                                          │
│  ── طلباتي ──                            │
│  (قائمة قصيرة لآخر العمليات + الحالة)    │
└──────────────────────────────────────────┘
```

| قاعدة | تفاصيل |
|--------|---------|
| عنوان الصفحة | **ماذا تريد أن تفعل؟** |
| بطاقات النية | نص العرض من الفهرس / لغة المنتج فقط |
| لا تبويبات تقنية | لا «شجرة / مناسبات / بطاقات» كتصنيف DB |
| مدخل التتبع | قسم «طلباتي» أو رابط مكافئ — حالات بشرية |

### 4.2 نموذج النية — حقائق قصيرة

تدفق موحّد لكل نية A–F:

```
اختيار النية → حقائق (١–٣ خطوات كحد أقصى) → مراجعة قصيرة → ابدأ الآن / إرسال
```

| قاعدة | تفاصيل |
|--------|---------|
| زر الإرسال | **ابدأ الآن** أو صياغة مكافئة من لغة المنتج — ليس «إنشاء طلب» / «إرسال البطاقة» |
| الخطوات | تجنّب معالج 5+ خطوات؛ إن لزم تقسيم، كل خطوة سؤال بشري واحد |
| اختيار الشخص | بحث بالاسم + سياق عائلي يعرضه النظام؛ التخزين الداخلي `person_id` — المستخدم لا يكتب id |
| تواريخ | عبر DateEngine (عرض هجري/ميلادي متزامن) — بلا `new Date` أعمال |
| مراجعة قبل الإرسال | ملخص: النية · الأسماء · التواريخ — بلغة بشرية |

#### حقائق دنيا مقترحة (تصميم — قابلة للضبط قبل الكود)

| النية | حقول الزائر (حد أدنى) | يبنيه النظام / لاحقًا |
|--------|------------------------|------------------------|
| أضف فردًا | الاسم · الجنس · أقرب سياق أب/عائلة (بحث) · تاريخ ميلاد إن وُجد | فرع · ربط · فحوصات VE |
| صحح بيانات | الشخص (بحث) · الحقول المتغيّرة فقط | مقارنة «الآن vs مقترح» للمندوب |
| أعلن وفاة | الشخص · تاريخ الوفاة | اتساق عائلي في VE |
| أعلن زواج | الطرف الأول · الطرف الثاني · التاريخ | تعارض زوجية في VE |
| شارك ذكرى | النص · وسائط اختيارية · أشخاص مرتبطون اختياريًا | حدود وسائط في VE |
| اطلب بطاقة | نوع البطاقة · المستهدف · حقول النوع | قواعد التكرار في VE/الخدمة |

### 4.3 بعد الإرسال — تأكيد + تتبع

```
┌──────────────────────────────────────────┐
│  تم الإرسال                              │
│  إضافة فرد · … · تم الإرسال              │
│                                          │
│  ● تم الإرسال                            │
│  ○ وصل للمندوب                           │
│  ○ تحت المراجعة                          │
│  ○ …                                     │
│                                          │
│  [ متابعة طلباتي ]   [ ابدأ شيئًا آخر ]  │
└──────────────────────────────────────────┘
```

| رمز WF | عرض الزائر |
|--------|------------|
| `submitted` | تم الإرسال |
| `assigned` | وصل للمندوب |
| `in_review` | تحت المراجعة |
| `needs_changes` | نحتاج معلومة إضافية منك |
| `approved` | تم قبول طلبك |
| `applied` | تمت إضافة البيانات |
| `done` | اكتمل |
| `rejected` | لم يُقبل (+ سبب مفهوم) |

**ممنوع في التتبع:** `tree_card` · `REQ-…` كعنوان وحيد · JSON · أسماء أعمدة.

### 4.4 نحتاج معلومة إضافية

عند `needs_changes` (من VE أو من المندوب عبر WF):

1. رسالة السبب بلغة بشرية (حقل/حقيقة ناقصة).  
2. نموذج قصير للحقول المطلوبة فقط.  
3. **تعديل** ثم **إعادة الإرسال**.  
4. العودة لمسار التتبع — نفس الطلب (لا إنشاء مكرر صامت).

### 4.5 فشل التحقق قبل الدخول للطابور

إن رفض VE الإرسال/التعيين:

| نتيجة VE | سلوك RX |
|----------|---------|
| يحتاج معلومة | نفس §4.4 — لا يُعرض كـ«مرفوض نهائي» إن كان قابلًا للتصحيح |
| مرفوض تحقق | سبب واضح · لا إرسال متكرر بنفس الحمولة الفاسدة دون تغيير |
| يمر | تسليم لـ WF · حالة «تم الإرسال» / التالية حسب المحرك |

RX **تعرض** نتيجة VE — **لا تعيد تنفيذ** قواعد الهوية/التكرار داخل الصفحة.

## 5) تسليم Validation Engine (عقد تصميم)

```
RX ──► { intent_type, facts[], person_refs[], submitter_context }
          │
          ▼
        VE
          │
          ├── pass      → WF ينشئ/يحدّث الحالة
          ├── needs_info → RX تعرض الحقول المطلوبة
          └── reject    → RX تعرض السبب (بلا طفرة شجرة)
```

| RX تفعل | RX لا تفعل |
|---------|------------|
| تجمع الحقائق وتتحقق شكلًا بسيطًا (حقل فارغ) | تقرّر تكرار أشخاص أو صحة نسب |
| تعرض أخطاء VE للمستخدم | تكتب على الشجرة عند «نجاح محلي» |
| تعيد الإرسال بعد التصحيح | تتخطّى VE «للسرعة» |

## 6) علاقة Workflow (استهلاك فقط)

| ما تستهلكه RX من WF | ما لا تبنيه RX |
|---------------------|----------------|
| الحالة الحالية بلغة المنتج | آلة حالات خاصة بالواجهة |
| إشعارات/تحديثات الحالة للعرض | تعيين المندوب يدويًا من الزائر |
| معرّف متابعة ثانوي إن لزم للدعم | مسار `status` قديم موازٍ كحقيقة |

أساس WF الحالي **provisional** — تصميم RX لا يفترض توسيع المحرك الآن؛ يفترض عقد العرض أعلاه.

## 8) As-Is → To-Be (الرئيسية فقط)

| As-Is | To-Be (RX v1) |
|-------|----------------|
| «إضافة بيانات للشجرة» / «إرسال البطاقة» | نية «أضف فردًا» + ابدأ الآن |
| حقول جد١…٤ ظاهرة كأساس | سياق أب/عائلة مختصر + بحث |
| مسارات مناسبة/ذكرى/بطاقة منفصلة اللغة | شبكة نوايا واحدة |
| تتبع ضعيف | مسار شحن موحّد |
| تفكير بطاقة/DB | تفكير فعل بشري |

الصفحة الحالية للزائر = **legacy تجربة** إلى أن يُشحن RX بعد اعتماد هذه المواصفة — **لا تجميل تدريجي بلا مواصفة**.
