## 1) الوحدة المشتركة (كل الأنواع)

```
نية في الرئيسية (Request Experience)
        ↓ حقائق قصيرة
Validation Engine          ← يتحقق — لا ينفّذ
        ↓ نتيجة واضحة (يمر / يحتاج معلومة / مرفوض تحقق)
Workflow Engine            ← حالة · مالك · تعيين · Audit · إشعار
        ↓
مراجعة / قرار (مندوب غالبًا · إدارة استثناءً أو أنواع مخصّصة)
        ↓ approved
تطبيق عبر الخدمة من الفهرس فقط (applied متحقَّق)
        ↓
أثر ظاهر + عودة للإدارة/الشجرة/الزائر · done
```

### 1.1 أدوار ثابتة

| الدور | يفعل | لا يفعل |
|--------|------|---------|
| **الزائر / مقدّم الطلب** | يختار نية · يقدّم حقائق · يعدّل عند «نحتاج معلومة» · يتابع الحالة بلغة بشرية | لا يبني الشجرة · لا يكتب `person_id` يدويًا · لا يتخطّى Workflow |
| **Validation Engine** | هوية · تكرار · تعارض · اكتمال · أسباب | لا يكتب شجرة · لا يغيّر حالة Workflow بمفرده كآلة حالات |
| **Workflow Engine** | حالة · مالك · انتقال · Audit · إشعار من الانتقال | لا يقرّر صحة النسب كبديل عن VE · لا UI |
| **المندوب** | يراجع في جلسة طلب · يعتمد / يطلب معلومة / يرفض (حسب الصلاحية) | لا محرّر فرع يومي لمسارات الفهرس · لا كتابة مباشرة على الشجرة |
| **الإدارة** | تراقب التدفق · تدخل استثنائي · أنواع مخصّصة (مثل سر المندوب) | ليست منزل تنفيذ المندوب · لا «راجع الشخص في الشجرة» كمسار أساسي |
| **Family Engine / الخدمات** | كتابة واحدة عند `approved → applied` فقط | لا تُستدعى من UI لتجاوز المحرك |

### 1.2 نقاط فرض Single Write Rule (كل الأنواع)

| نقطة | الفرض |
|------|--------|
| **RX** | يجمع حقائق الطلب فقط — **ممنوع** insert/update على `tree_*` / أحداث معتمدة / memory / cards خارج الطلب |
| **VE** | يقرّر قابلية المسار — **ممنوع** الكتابة على الشجرة |
| **WF** | يملك الحالة — التطبيق عبر انتقال `approved → applied` فقط |
| **DW** | أدوات سياق داخل الجلسة — **ممنوع** مسار «اختر شخصًا ثم أضف ابن/زوجة» ككتابة يومية لمسارات الفهرس |
| **Admin** | مراقبة / تدخل عبر المحرك — **ممنوع** مسار موازٍ يكتب الشجرة لنفس النية |
| **Legacy `alzidan-tree`** | ❄️ تجميليًا مجمّد — مسارات الكتابة المباشرة دين تقني يُغلق في Family Engine Alignment |

### 1.3 منع التكرار · خلط الأشخاص · التنفيذ المزدوج (قواعد عامة)

| خطر | آلية المنع (To-Be) |
|------|---------------------|
| **تكرار التنفيذ** | انتقال واحد `approved → applied` · قفل صف الطلب · Idempotency على `request_id` · رفض apply ثانٍ إن الحالة ≥ `applied` |
| **تعديل الشجرة خارج Workflow** | Single Write Rule + إغلاق مسارات UI المباشرة لمسارات الفهرس + Audit يفضح الكتابة بلا `request_id` |
| **خلط الأشخاص / سجلات مكررة** | VE يفرض `person_id` (لا الاسم وحده) · فحص تكرار قبل التعيين وقبل `applied` · المندوب يرى «المسجّل الآن vs المقترح» |
| **ازدواج مسار قديم** | إزالة `status` القديمي كمالك حقيقة عند إغلاق WF على السلّم |

### 1.4 لغة الحالة (ثلاث جماهير) — مصدر: [`PRODUCT-LANGUAGE.md`](./PRODUCT-LANGUAGE.md)

| رمز WF | الزائر | الإدارة (نظام/تشغيل) | المندوب |
|--------|--------|----------------------|---------|
| `submitted` | تم الإرسال | مُقدَّم | — (لم يُعيَّن بعد) |
| `assigned` | وصل للمندوب | مُعيَّن | في طابورك — لم تبدأ بعد |
| `in_review` | تحت المراجعة | قيد المراجعة | تحت مراجعتك الآن |
| `needs_changes` | نحتاج معلومة إضافية منك | يحتاج تعديل | بانتظار معلومة من المقدّم |
| `approved` | تم قبول طلبك | تمت الموافقة | مقبول — بانتظار التطبيق |
| `applied` | تمت إضافة البيانات / تم التنفيذ | طُبّق | نُفِّذ — راجع التالي |
| `done` | اكتمل | مكتمل | مكتمل |
| `rejected` | لم يُقبل (+ سبب) | مرفوض | مرفوض (+ سبب) |

## 2) As-Is مقابل To-Be — تدفق القرار

| البعد | As-Is (اليوم) | To-Be (بعد الاعتماد) |
|-------|---------------|----------------------|
| نقطة الدخول | نماذج متفرقة («بطاقة» · مناسبة · محرّر مندوب) | نية واحدة من الفهرس في RX |
| التحقق | متأخر / SQL خام / غير موحّد | **Validation Engine** قبل المندوب والشجرة |
| القرار | إدارة تقبل/ترفض أحيانًا · مندوب يكتب مباشرة أحيانًا | قرار داخل جلسة طلب عبر WF · صلاحية Delegates |
| التنفيذ | apply إداري جزئي + كتابة UI مباشرة | خدمة الفهرس فقط عند `applied` متحقَّق |
| منع التكرار | ضعيف | قفل طلب + Idempotency + VE تكرار |
| تتبع الزائر | ضعيف/غير موحّد | حالات لغة المنتج أعلاه |
| الإدارة | مشغّل طلبات + محرّر أشخاص | مراقب تدفق + استثناء |
| المندوب | tree-first legacy | Inbox → جلسة → قرار → التالي |
| الترتيب | شاشات منفردة | RX → **VE** → WF → DW → Admin |

### A) أضف فردًا — `tree_card`

| بند | الجواب |
|-----|--------|
| **من أنشأ الطلب؟** | الزائر من الرئيسية (أو مندوب لاحقًا عبر نية منظمة — لا كتابة مباشرة) |
| **من يراجعه؟** | المندوب المعيَّن للفرع (بعد VE تمرير + `assigned`) |
| **من يعتمد أو يرفض؟** | المندوب المالك (`in_review → approved/rejected`) · الإدارة تدخل استثنائي عبر WF فقط |
| **ماذا يرى المندوب؟** | النية «أضف فردًا» · الحقائق · مرشّح الأب/الربط الذي بناه النظام · نتيجة VE · مقارنة مع أقرب تطابقات |
| **ماذا يحدث بعد التنفيذ؟** | `applied`: إنشاء/ربط الشخص عبر Family Engine · إشعار الزائر «تمت إضافة البيانات» · الإدارة ترى أثرًا في التدفق · الشجرة تعكس الفرد |
| **منع تكرار التنفيذ** | apply مرة واحدة لكل `request_id` · رفض إن وُجد شخص بنفس البصمة بعد apply سابق |
| **منع تعديل الشجرة خارج WF** | إغلاق إضافة ابن/فرد من Person hub كمسار يومي |
| **منع خلط/تكرار أشخاص** | VE: `parent_person_id` إلزامي عند الإمكان · فحص تكرار اسم+سياق+تاريخ · لا اعتماد على سلسلة أسماء الجد وحدها |
| **هل يمكن التراجع؟** | بعد `applied`: ليس «Undo زر» — تصحيح بطلب `tree_edit` أو إجراء إداري موثّق عبر المحرك · قبل `applied`: رفض / needs_changes |
| **هل تسبب تضارب شجرة؟** | نعم إن رُبط بأب خاطئ أو وُلد مكرّر أو ترتيب ميلاد متعارض — VE يوقف قبل الاعتماد |
| **من يبدأ · يراجع · يعتمد · ينفّذ · بعد** | زائر → VE → مندوب يراجع/يعتمد → المحرك+Family Engine ينفّذ → أثر+إشعار+done |
| **نقاط VE** | اكتمال الاسم/الجنس حسب السياسة · هوية الأب · تكرار · تعارض فرع/صلاحية · سلامة هيكل قبل `assigned` وأعادتها قبل `applied` |
| **لغة الحالة** | زائر: تم الإرسال…تمت إضافة البيانات · مندوب: في طابورك / تحت مراجعتك · إدارة: مُقدَّم…طُبّق |

### B) صحح بيانات — `tree_edit`

| بند | الجواب |
|-----|--------|
| **من أنشأ الطلب؟** | الزائر (أو صاحب صلاحية لاحقًا) على شخص موجود بـ `person_id` |
| **من يراجعه؟** | المندوب المعيَّن |
| **من يعتمد أو يرفض؟** | المندوب · إدارة استثناءً |
| **ماذا يرى المندوب؟** | **المسجّل الآن vs المقترح** حقلًا بحقل · تحذيرات VE (تعارض تاريخ وفاة/ميلاد…) |
| **بعد التنفيذ؟** | تحديث عبر Family Engine · Audit يربط الطلب بالحقول · إشعار «تمت إضافة البيانات/تم التصحيح» بلغة المنتج |
| **منع تكرار التنفيذ** | Idempotent patch على نفس `request_id` · لا apply إن الحقول المطبّقة = المقترح مسبقًا بنفس الطلب |
| **منع خارج WF** | إغلاق محرّر الشخص في المندوب كمسار تصحيح يومي للفهرس |
| **منع خلط أشخاص** | الطلب يحمل `person_id` فقط — ممنوع التصحيح بالاسم |
| **هل يمكن التراجع؟** | طلب تصحيح لاحق يعيد القيم · أو إجراء إداري موثّق — لا حذف صامت للتاريخ |
| **تضارب شجرة؟** | نعم إن صحّح نسب/تواريخ تكسر الهيكل — VE قبل الاعتماد وقبل apply |
| **من يبدأ…بعد** | زائر → VE → مندوب قرار → FE apply → أثر للإدارة والشجرة |
| **نقاط VE** | وجود الشخص · فرق حقول غير فارغ · تعارض منطقي تواريخ · صلاحية الفرع |
| **لغة الحالة** | كالمسار العام · عند needs_changes: «نحتاج معلومة إضافية منك» + الحقل المطلوب |

### C) أعلن وفاة — `event_death`

| بند | الجواب |
|-----|--------|
| **من أنشأ؟** | الزائر / ذو علاقة عبر RX |
| **من يراجع؟** | المندوب |
| **من يعتمد/يرفض؟** | المندوب (حساسية عالية — سبب رفض إلزامي) |
| **ماذا يرى المندوب؟** | الشخص المستهدف · التاريخ المقترح · حالة الحياة الحالية · تحذير إن وُجدت مناسبات لاحقة |
| **بعد التنفيذ؟** | تحديث حالة الحياة/تاريخ الوفاة + حدث مجال عبر FE · إشعار · انعكاس على البطاقات/العرض حيث ينطبق |
| **منع تكرار التنفيذ** | لا وفاة ثانية على نفس `person_id` من طلب آخر إن مطبّقة · VE يرفض التكرار |
| **منع خارج WF** | لا تبديل «متوفّى» من محرّر المندوب دون طلب |
| **منع خلط** | `person_id` إلزامي |
| **تراجع؟** | حساس: تصحيح بطلب لاحق + Audit — ليس زر تراجع سريع |
| **تضارب؟** | عالي — تواريخ أبناء بعد الوفاة · مناسبات لاحقة · VE يمنع |
| **من يبدأ…بعد** | زائر → VE → مندوب → FE → إدارة ترى الحدث في التدفق |
| **نقاط VE** | هوية · ليس متوفّى مسبقًا · اتساق التاريخ مع الميلاد والأبناء · اكتمال سبب/تاريخ حسب السياسة |
| **لغة** | زائر: «أعلن وفاة» + حالات الشحن · مندوب: طلب حسّاس في الطابور · إدارة: إعلان وفاة · الحالة |

### D) أعلن زواج — `event_marriage`

| بند | الجواب |
|-----|--------|
| **من أنشأ؟** | الزائر |
| **من يراجع؟** | المندوب |
| **من يعتمد/يرفض؟** | المندوب |
| **ماذا يرى المندوب؟** | الطرفان (معرّفات) · التاريخ · هل يوجد ربط زوجية قائم · نتيجة VE |
| **بعد التنفيذ؟** | حدث زواج + ربط زوجية عبر FE حسب العقد · إشعار |
| **منع تكرار** | لا تطبيق مزدوج لنفس الطرفين/الطلب · VE يكتشف زواج قائم متعارض |
| **منع خارج WF** | لا «إضافة زوجة» صامتة من Person hub |
| **منع خلط** | معرّفا الطرفين — لا الأسماء وحدها |
| **تراجع؟** | تصحيح/فسخ لاحق كنية منفصلة إن لزم (صف فهرس) — ليس حذفًا صامتًا |
| **تضارب؟** | زوج قائم · تعدد مخالف للسياسة · طرف غير موجود — VE |
| **من يبدأ…بعد** | زائر → VE → مندوب → FE → أثر شجرة + مناسبة |
| **نقاط VE** | وجود الطرفين · صلاحية فرع · تعارض زوجية · اكتمال التاريخ |
| **لغة** | «أعلن زواج» عبر الثلاث لغات |

### E) شارك ذكرى — `memory_card`

| بند | الجواب |
|-----|--------|
| **من أنشأ؟** | الزائر |
| **من يراجع؟** | المندوب (إن لزم حسب السياسة) أو مسار اعتماد الذكريات عبر نفس عُقد WF |
| **من يعتمد/يرفض؟** | المندوب / سياسة النوع |
| **ماذا يرى المندوب؟** | النص/الوسائط · الأشخاص المرتبطون · نتيجة VE (روابط أشخاص) |
| **بعد التنفيذ؟** | Memory Service عند `applied` · ظهور الذكرى المعتمدة |
| **منع تكرار** | Idempotent على `request_id` · لا نشر مزدوج |
| **منع خارج WF** | لا نشر ذكرى من لوحة المندوب يتجاوز الطلب لنوايا الفهرس |
| **منع خلط** | روابط `person_id` اختيارية لكن إن وُجدت تُتحقق |
| **تراجع؟** | إخفاء/سحب إداري عبر خدمة الذاكرة + Audit — حسب سياسة لاحقة |
| **تضارب شجرة؟** | منخفض على الهيكل · متوسط إن رُبط بشخص خاطئ |
| **من يبدأ…بعد** | زائر → VE → قرار → Memory → أثر |
| **نقاط VE** | اكتمال المحتوى · سلامة الروابط · حدود وسائط |
| **لغة** | «شارك ذكرى» · حالات الشحن العامة |

### F) اطلب بطاقة — `special_card`

| بند | الجواب |
|-----|--------|
| **من أنشأ؟** | الزائر |
| **من يراجع؟** | المندوب أو مسار البطاقات المعتمد عبر WF |
| **من يعتمد/يرفض؟** | حسب صلاحية النوع |
| **ماذا يرى المندوب؟** | نوع البطاقة · المستهدف · الحقول · VE |
| **بعد التنفيذ؟** | Cards عند `applied` |
| **منع تكرار** | لا بطاقة مكررة لنفس الطلب · قواعد تكرار النوع في VE/الخدمة |
| **منع خارج WF** | لا إصدار بطاقة من UI إداري يتجاوز المحرك لنوايا الفهرس |
| **منع خلط** | مستهدف بـ `person_id` إن لزم |
| **تراجع؟** | إبطال بطاقة عبر خدمة Cards + سجل — سياسة لاحقة |
| **تضارب شجرة؟** | منخفض |
| **من يبدأ…بعد** | زائر → VE → قرار → Cards → أثر |
| **نقاط VE** | اكتمال حقول النوع · وجود المستهدف · صلاحية |
| **لغة** | «اطلب بطاقة» |

### G) إعادة تعيين الرقم السري — `delegate_secret_reset`

| بند | الجواب |
|-----|--------|
| **من أنشأ؟** | الإدارة (نية تشغيلية — ليس كروم الشجرة/المناسبات) |
| **من يراجع؟** | الإدارة |
| **من يعتمد أو يرفض؟** | الإدارة فقط — أزرار: اعتماد وإصدار رقم سري جديد · رفض |
| **ماذا يرى المندوب؟** | **لا** يرى طلبًا في طابور الشجرة · قد يستلم الرقم الجديد عبر القناة الآمنة بعد الاعتماد (خارج جلسة tree) |
| **بعد التنفيذ؟** | `maint.delegate_secret_reset_v1` (SQL Workspace / أوامر صيانة) · أثر على دخول المندوب · Audit |
| **منع تكرار التنفيذ** | أمر صيانة لمرة لكل طلب معتمد · رفض إعادة إصدار صامت بلا طلب جديد |
| **منع تعديل الشجرة** | هذا النوع **لا يمس الشجرة** — مسار مخصّص |
| **منع خلط أشخاص** | ربط بمندوب/فرع معرّف — ليس بالاسم المعروض وحده |
| **تراجع؟** | لا «تراجع» للرقم القديم بعد الإصدار — إعادة تعيين جديدة بطلب جديد |
| **تضارب شجرة؟** | لا |
| **من يبدأ…بعد** | إدارة تنشئ → إدارة تعتمد → صيانة تنفّذ → مندوب يستخدم السر الجديد |
| **نقاط VE** | وجود المندوب · تفعيل · عدم تكرار طلب مفتوح مزدوج · صلاحية الطالب الإدارية |
| **لغة الحالة** | إدارة: طلب إعادة تعيين الرقم السري · المندوب · الفرع · بانتظار الإدارة / تم الإصدار / مرفوض · **لا** تُعرض انتقالات «مُعيَّن/شجرة/مناسبات» العامة |
| **WF** | عُقد مبسّطة أو شاشة مخصّصة كما في الفهرس — بلا كروم الشجرة |

### H–K) مرشّحات — ملخّص مؤجّل

جداول الرحلة التفصيلية لـ H/I/J/K تبقى مرجعًا تصميميًا عند فتح صف الفهرس لاحقًا.  
**لا تُنفَّذ · لا تُعرض في RX v1 · لا تُحسم هنا باختراع منتج.**

| # | قبل أي كود | ملاحظة |
|---|------------|--------|
| H أضف زوجة | صف فهرس + قرار: نية مستقلة أم جزء من «أعلن زواج»؟ | ⬛ |
| I أضف أبناء | صف فهرس + قرار: نية مستقلة أم امتداد «أضف فردًا»؟ + ذرّية apply | ⬛ |
| J أعلن ميلاد | صف فهرس + قرار الربط مع `tree_card` | ⬛ |
| K مناسبة عامة | تجميع عرض فقط — كل مناسبة = صف فهرس | ⬛ |

## 5) نقاط Validation Engine — ملخص جدولي

| النوع | قبل التعيين | قبل الاعتماد | قبل applied |
|-------|-------------|--------------|-------------|
| `tree_card` | اكتمال · أب/سياق · تكرار أوّلي | تعارض هيكل · صلاحية | إعادة فحص تكرار + هوية |
| `tree_edit` | وجود شخص · فرق حقول | تعارض تواريخ/نسب | بصمة الحقول vs الحالي |
| `event_death` | هوية · ليس متوفّى | اتساق عائلي | منع وفاة مزدوجة |
| `event_marriage` | طرفان | تعارض زوجية | منع apply مزدوج |
| `memory_card` | اكتمال · روابط | سياسة محتوى | Idempotent نشر |
| `special_card` | حقول النوع | مستهدف | منع بطاقة مكررة للطلب |
| `delegate_secret_reset` | مندوب موجود/مفعّل | صلاحية إدارة | منع إصدار مزدوج لنفس الطلب |
| مرشّحات H–J | لا تُفعّل فحوصات إنتاج بلا صف فهرس | — | — |

**Truth Before Speed:** أي فشل VE في الصفوف أعلاه = لا اعتماد سريع ولا طفرة شجرة.
