# عائلة الزيدان — Engineering Roadmap (إدارة مشروع + مرجع هندسي)

**الحالة:** معتمد رسميًا — وثيقة إدارة مشروع (ليست قائمة مزايا فقط)  
**التاريخ:** 2026-08-07  
**آخر تحديث تخطيط:** 2026-08-08 — ترقية إلى نموذج حالات صريح · ثلاثة برامج · Tree Engine v2 · دين تقني · قواعد انحدار · DateEngine كبنية تحتية  
**القرارات المعمارية المقفلَة:** [`docs/ADR.md`](./ADR.md)

وثيقة التنفيذ الهندسية الرسمية لمشروع عائلة الزيدان. تعالج جذور المشاكل حسب طبقات النظام، وتُدار كـ**برنامج مشاريع** بثلاثة مسارات واضحة + بنية تحتية مشتركة.

**سياسة عامة للمشروع:** لا «مقبول / تم» بلا تطبيق متحقَّق — على الطلبات، الصور، الزوجات، الدمج، وأي اعتماد لاحق.

**الهدف التنفيذي الحالي:** إكمال نشر SQL المعلّق (Delegates v2 · tree-import reuse · Integrity v2) → فرض صلاحيات المندوب → ثم Admin UX. UX الموبايل **بعد** مراحل الإدارة فقط.

## 2) Canonical Person Identity

```
person_id          ← هوية مستقلة مستقرة
    ↓
Node Path          ← موقع كانوني في الشجرة
    ↓
Display Name       ← للعرض
    ↓
Search Name        ← للبحث/التطبيع
```

كل كتابة تمر بـ `person_id`. ممنوع الربط الغامض بالاسم (`limit(1)` / `min()` على تطابق متعدد) **عند توفّر `person_id`**.

## 5) بنية تحتية — DateEngine (ADR-009)

**ليست ملاحظة جانبية.** DateEngine طبقة بنية تحتية مشتركة عبر البرامج الثلاثة.

| # | البند | الحالة |
|---|--------|--------|
| **DE-1** | مكتبة `assets/js/modules/date-engine.js` (parse / validate / convert / format / normalizeDigits / synced pair / timestamp guard) | 🟢 |
| **DE-2** | ADR-009 + حظر `new Date()` لتواريخ الأعمال | 🟢 موثّق |
| **DE-3** | مستهلك أول: حارس + تحقق حي على `polls-ends-at` | 🟢 |
| **DE-4** | ربط **كل** نماذج الميلاد/الوفاة/المناسبات بـ `toSyncedPair` | ⚪ دين تقني |
| **DE-5** | هجرة مخطط تدريجية لأعمدة `*_g` / `*_h` حيث ينقص الزوج | ⚪ — ليست في الجولة الحالية |

**قاعدة غير قابلة للتفاوض:** أي تاريخ أعمال جديد → DateEngine. أعمدة `timestamptz` ميلادية ترفض سنوات هجرية (`DATE-002`). انظر أيضًا § قواعد الانحدار.

## 6) Tree Engine v2 — مرحلة مستقلة

مرحلة منتج/معمارية **خاصة** (وليست بندًا فرعيًا تحت Admin UX). تُنفَّذ بعد استقرار الكتابة الحالية وIntegrity قراءة فقط، وقبل توسيع إصلاحات تلقائية واسعة.

| القدرة | الوصف | الحالة |
|--------|--------|--------|
| **person_id فقط** | كل نقل/ربط/دمج عبر UUID؛ لا مسار اسم عند وجود هوية | ⚪ (جزئيًا مفروض في مسارات الكتابة الحالية 🟢) |
| **لا name link** | إزالة بقايا حل الأب/الشخص بالاسم في محرك الشجرة | ⚪ دين تقني |
| **Duplicate detection** | اكتشاف أشخاص/عقد مكررة قبل الدمج | ⚪ |
| **Merge persons** | دمج هويتين مع سجل تدقيق + dry-run | ⚪ |
| **Move branches** | نقل فرع تحت أب جديد بـ `person_id` | ⚪ |
| **Dry Run** | كل عملية كتابة تعرض أثرًا متوقعًا قبل التنفيذ | ⚪ إلزامي عند البدء |
| **Rollback** | مسار استرجاع موثّق لكل عملية جماعية | ⚪ |

**علاقة بالبرامج:** تخدم برنامج (أ) إصلاح البيانات وتُغذي Admin عبر موديول الشجرة — دون خلطها مع مزايا تطبيق (ج).

## 8) قواعد الانحدار (Regression Rules) — غير قابلة للتفاوض

تُراجع في كل PR يمس الشجرة أو الاعتماد أو التواريخ أو الواجهة الإدارية:

| # | القاعدة |
|---|---------|
| **R-1** | **لا ربط بالاسم إذا توفّر `person_id`** — أي `limit(1)` / تطابق اسم متعدد مع تجاهل UUID = رفض |
| **R-2** | **لا حذف تدميري مباشر من الواجهة بلا ضمانات** — تأكيد صريح + (حيث ينطبق) dry-run / صلاحية / أثر معروض |
| **R-3** | **إصلاحات الشجرة تبدأ بـ Dry Run** — لا Apply صامت |
| **R-4** | **لا تُعرض أخطاء Supabase الخام للمستخدم النهائي** — رسالة عربية + رمز خطأ (`TREE-*` / `REQ-*` / …) |
| **R-5** | **كل تواريخ الأعمال عبر DateEngine** — لا `new Date(...)` لتواريخ المجال (ADR-009) |
| **R-6** | **تغييرات الشجرة → Audit** — كل اعتماد/إصلاح/دمج/نقل يكتب سجلًا قابلًا للمراجعة |
| **R-7** | **Health Center قراءة فقط** — ممنوع auto-repair من واجهة مركز الصحة |

خرق أي قاعدة أعلاه يوقف إغلاق البند حتى التصحيح أو ADR جديد صريح.

## 9) Architecture Decisions (ADR)

قرارات معمارية **مقفلة** — ليست اقتراحات. التفاصيل الكاملة في [`docs/ADR.md`](./ADR.md).

| ADR | القرار |
|-----|--------|
| ADR-001 | الهوية تعتمد على `person_id` (Canonical Person Identity) |
| ADR-002 | ممنوع الربط بالاسم عند الكتابة |
| ADR-003 | Event Bus هو المصدر الوحيد لأحداث المجال بعد الاعتماد |
| ADR-004 | Health Center مرجع صحة البيانات (Diagnostics للتفاصيل التقنية) |
| ADR-005 | محرك شجرة واحد — Web / Admin / Mobile بلا محركات متباعدة |

أي خرق لهذه القرارات يُوقف الإغلاق حتى يُصحَّح أو يُوثَّق ADR جديد صراحةً.

## 18) Data Integrity Engine

محرك **دائم** (برنامج أ): أبناء بلا أب، أب بلا فرع، `parent_person_id`، `person_id` مكرر، cycles، زوجة بلا زوج، أبناء خارج الفرع، `approved` بلا أثر، أخبار منتهية ظاهرة. يغذي Health Center.

**للتخطيط:** مسار Integrity قراءة فقط = 🟢 مغلق كمفهوم. نشر v2 SQL = 🟡. أي إصلاح كتابة لاحق = dry-run + موافقة صريحة (R-3) → مسار Tree Engine v2 / Repair اليدوي فقط.

## 21) Definition of Done

لا يُعتبر البند 🟢 إلا إذا:

- [ ] اجتاز **Smoke Tests**
- [ ] اجتاز **Regression Tests** (ومنها قواعد §8)
- [ ] لا أخطاء غير مفسَّرة في **Health Center**

- [ ] تم تحديث **Compatibility Matrix**
- [ ] لا **Error Codes** جديدة غير مفسَّرة
