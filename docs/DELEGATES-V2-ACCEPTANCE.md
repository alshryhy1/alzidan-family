# بوابة 1 — اختبار قبول Delegates v2 (عربي · تنفيذي)

**الحالة:** 🟡 بانتظار تنفيذ صاحب المنتج / المدير في الإدارة — **ليس برمجة جديدة**  
**التاريخ:** 2026-08-09  
**الغرض:** إغلاق بوابة Delegates v2 → 🟢 حتى يُسمح بتجميد الدستور الحي ثم Request Experience  
**المراجع:** [`DELEGATES-V2-PHASE2.md`](./DELEGATES-V2-PHASE2.md) · [`ENGINEERING-ROADMAP.md`](./ENGINEERING-ROADMAP.md) · SQL: `supabase/sql/COPY-ME-delegates-v2.sql` + `COPY-ME-delegates-v2-enforce.sql`

> **قاعدة:** لا ميزات مندوب جديدة · لا تحسين تجميلي لصفحة المندوب · لا كود Delegate Workspace.  
> النجاح هنا = **اختبار قبول** على الإنتاج (أو بيئة الهدف) + تعليم الخانات أدناه.

## 0) قبل البدء (دقيقة واحدة)

| # | جاهزية | ☐ |
|---|--------|---|
| 0.1 | ملفّا COPY-ME طُبّقا على Supabase (أساس ثم Enforce) — إن شُكّ فأعد اللصق من الملفات لا من الشات | ☐ |
| 0.2 | Hard Refresh لصفحة الإدارة (`Cmd/Ctrl+Shift+R`) | ☐ |
| 0.3 | لديك حساب مدير + مندوب اختبار (فرع معروف) + إمكانية فتح بوابة المندوب بنفس بيانات الدخول | ☐ |

افتح الإدارة: `/pages/admin.html#module=delegates`

## 1) اختبار الصلاحيات (عمليات حسب الدور)

| # | الخطوة | النتيجة المتوقعة | ☐ نجح |
|---|--------|-------------------|-------|
| 1.1 | إدارة → المندوبون → **مزامنة من الطلبات القديمة** (إن وُجدت) | القائمة تعرض مندوبين مع دور/فرع/`مفعّل` | ☐ |
| 1.2 | عيّن لمندوب اختبار دور **`viewer`** (عرض فقط) | الدور يظهر في القائمة + صف تدقيق لتغيير الدور | ☐ |
| 1.3 | من بوابة المندوب: حاول **حفظ/تعديل شجرة** أو **مناسبة** | **رفض** برسالة عربية واضحة («دورك الحالي لا يسمح…» أو ما يعادلها) — **لا** نجاح صامت | ☐ |
| 1.4 | غيّر الدور إلى **`branch_editor`** أو **`full_delegate`** | الكتابة المسموحة حسب الدور **تنجح** | ☐ |
| 1.5 | (إن وُجد) مندوب بلا صف `delegates_v2` بعد | يبقى على مسار legacy حتى المزامنة — لا عطل للإدارة | ☐ |

**معيار إغلاق بند «الصلاحيات»:** 1.2 + 1.3 + 1.4 كلها ناجحة.

## 2) اختبار الأدوار

| # | الخطوة | النتيجة المتوقعة | ☐ نجح |
|---|--------|-------------------|-------|
| 2.1 | غيّر دور مندوب من دور أ إلى دور ب من الإدارة | التحديث يظهر فورًا بعد التحديث/إعادة الفتح | ☐ |
| 2.2 | افتح **سجل التدقيق** لنفس المندوب | صف يوضح الدور **السابق** والدور **الجديد** (`previous_role_key` ظاهر أو مكافئه في الواجهة) | ☐ |
| 2.3 | فرع المندوب (`branch_key`) ظاهر وغير فارغ للمندوبين المتزامنين | لا مندوب «بلا فرع» بعد المزامنة الناجحة | ☐ |

**معيار إغلاق بند «الأدوار»:** 2.1 + 2.2 ناجحان.

## 3) اختبار التفعيل والتعطيل

| # | الخطوة | النتيجة المتوقعة | ☐ نجح |
|---|--------|-------------------|-------|
| 3.1 | من الإدارة: **عطّل** مندوب اختبار | الحالة = معطّل في القائمة | ☐ |
| 3.2 | حاول الدخول أو الكتابة من بوابة المندوب وهو معطّل | **رفض** برسالة التعطيل («حساب المندوب معطّل…») | ☐ |
| 3.3 | **فعّل** المندوب مجددًا بدور يسمح بالكتابة | الدخول/الكتابة المسموحة تعود | ☐ |
| 3.4 | تحقق من سجل التدقيق | صفوف تفعيل/تعطيل موجودة ومرتبة زمنيًا | ☐ |

**معيار إغلاق بند «التفعيل/التعطيل»:** 3.1 + 3.2 + 3.3 ناجحة.
