# استرجاع نسخة Patch 0 — 2026-08-07

## المحتويات

- `json/*.json` — لقطات جداول حرجة
- `meta/integrity-scan.json` — نتائج الفحص
- `meta/table-probe.txt` — اكتشاف الجداول عبر REST

## متى تستخدم

بعد فشل Validation في Patch لاحق، أو عند الحاجة لإعادة صفوف محددة كما كانت قبل التعديل.

## استرجاع مفضّل (عند توفر صلاحيات DB)

1. خذ dump جديدًا للحالة الحالية قبل الاسترجاع (لا تستبدل على عمياء).
2. لجدول واحد، مثال مفاهيمي عبر SQL/`psql` أو لوحة Supabase:
   - فرّغ أو احذف الصفوف المستهدفة بحذر (حسب نطاق الضرر).
   - استورد من الملف المقابل في `json/` مع الحفاظ على `id` / `person_id` إن وُجدت.
3. أعد تشغيل Integrity Scan وقارن مع `meta/integrity-scan.json`.

## استرجاع عبر REST / service_role

1. اضبط `SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY` محليًا (لا تُرفع إلى git).
2. لكل ملف في `json/`:
   - اقرأ المصفوفة.
   - `POST` مع `Prefer: resolution=merge-duplicates,return=minimal` و`on_conflict` المناسب للجدول.
3. لا تستخدم مفتاح `anon` للكتابة على الشجرة.

## تحذيرات

- الملفات تحتوي بيانات عائلية — لا تُرفع إلى git ولا تُشارك علنًا.
- `approval_requests.json` فارغ في هذه اللقطة بسبب RLS على `anon`؛ لا تعتمد عليه لاسترجاع الطلبات.
- أي كتابة استرجاع يجب أن تمر عبر `person_id` حيثما وُجد (ADR-001/002).
