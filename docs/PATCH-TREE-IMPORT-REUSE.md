# Patch — استيراد tree_card بدون تكرار الأب

**التاريخ:** 2026-08-08  
**الحالة:** مكتمل على طبقة العميل + SQL جاهز للتطبيق  
**المرجع:** ADR-001/002 · Patch 2 verified apply · متطلب: «إذا الأب موجود يُضاف الابن ولا يُكرَّر الأب»

---

## 1) السلوك قبل / بعد

| | قبل | بعد |
|--|-----|-----|
| سلسلة `tree_rows` كاملة (محمد→…→حبيب→محمد) والأب حبيب موجود | قد تُعاد إدراج حواف الأسلاف / نسخة ثانية من الأب | تُحلّ كل عقدة موجودة وتُتخطى؛ يُدرج الابن الجديد فقط تحت حبيب الحالي |
| `father_person_id` منسوخ على كل حافة سلف (بيانات قديمة) | قد يربط كل الحواف بنفس الأب خطأً | يُتجاهل `person_id` إذا تعارض مع مسار الحافة |
| أب غامض (نفس الاسم لأكثر من شخص) | اختيار صامت أو تكرار | فشل عربي صريح `TREE-001` |

---

## 2) ماذا تغيّر؟

1. **`importTreeCardToTree`** (`assets/js/modules/request-actions.js`):
   - حل الأب من الشجرة (`person_id` / مسار / تطابق فريد).
   - إن وُجد الابن تحت ذلك الأب → تخطٍ وإعادة استخدام؛ **لا** استيراد أعمى لكل `tree_rows`.
   - إدراج الحواف الناقصة فقط.
2. **`buildTreeCardRows`**: لا يلصق `father_person_id` على كل أسلاف السلسلة.
3. **SQL** `supabase/sql/20260808_tree_import_reuse_existing.sql` + `COPY-ME-tree-import-reuse-existing.sql`:
   - إعادة نشر `admin_tree_children_import_v1` بنفس سياسة إعادة الاستخدام + `TREE-001` عربي عند غموض الأب.

---

## 3) SQL — تطبيق الإنتاج

افتح الملف والصق محتواه كاملًا في Supabase SQL Editor (بدون سياج markdown):

`supabase/sql/COPY-ME-tree-import-reuse-existing.sql`

---

## 4) إعادة الاختبار (طلب معلّق)

1. انشر أصول Admin المحدَّثة.
2. طبّق SQL أعلاه إن لم يُطبَّق.
3. طلب مثال: **حبيب محمد** / فرع **زايد** و`tree_rows` تبني محمد→غازي→فايز→زيدان→حبيب→محمد.
4. تأكد أن حبيب موجود مسبقًا في الشجرة.
5. من طلبات الإدارة: **قبول** أو **إعادة تطبيق**.
6. المتوقع: صف ابن واحد جديد تحت حبيب الحالي؛ **لا** صف حبيب ثانٍ؛ ملخص مثل: `جديد: 1، موجود مسبقاً: N، متحقق: …`.
7. إن كان اسم الأب يطابق أكثر من شخص بلا `parent_person_id` فريد → رسالة `TREE-001` عربية ورفض الاعتماد.
