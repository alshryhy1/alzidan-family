# SQL Workspace — تقرير التسليم

**التاريخ:** 2026-08-09  
**الحالة:** واجهة ✅ · أوامر صيانة جاهزة ✅ · طابور يومي + أرشيف ✅ · RPC تنفيذ 🟡 حتى يُشغَّل أمر الترقية من الإدارة  
**المسار:** `pages/admin.html` → بعد الدخول → **⚙ أدوات الصيانة** (`#module=tools`)

## قاعدة تشغيل (Standing rule)

**أي SQL صيانة/إصلاح جديد يُسلَّم كأمر جاهز داخل SQL Workspace** (تشغيل من الإدارة + تعليمه **مُنفذ** / نقله للأرشيف).  
ملفات `supabase/sql/*.sql` تبقى مصدر الحقيقة في المستودع.  
**لا** يُطلب من المشغّل لصق COPY-ME في Supabase إلا لسبب تقني موثّق — حاليًا: ترقية المنفّذ القديم الذي يرفض أجسام الدوال (`SQL-WS-MULTI`) مرة واحدة عبر preset `maint.sql_workspace_literal_aware_v1` أو ملفه إن فشل من الواجهة.

## أوامر الصيانة الجاهزة (Presets)

تظهر أعلى مساحة SQL تحت عنوان **أوامر الصيانة الجاهزة** — بطاقات تشغيل واضحة، وليست داخل المحرر فقط.

| المعرّف | العنوان | ملف المصدر |
|---------|---------|------------|
| `maint.sql_workspace_literal_aware_v1` | ترقية منفّذ SQL Workspace | `20260809_sql_workspace_literal_aware.sql` |
| `maint.fix_delegate_portal_path_v1` | إصلاح دخول المندوب بعد القبول (بوابة 1) | `COPY-ME-fix-delegate-portal-path.sql` |
| `maint.delegate_secret_reset_v1` | طلب إعادة تعيين الرقم السري | `COPY-ME-delegate-secret-reset.sql` |

التشغيل: **تشغيل** (متسلسل) → عند النجاح يُعلَّم **مُنفذ** ويُنقل إلى **سجل التنفيذ / الأرشيف** (يختفي من شاشة العمل اليومية).

### لماذا قد تبدو المساحة فارغة؟

- الموقع الحي المبني من `origin/main` القديم كان فيه محرر SQL فقط **بدون** كتالوج الأوامر — الكتالوج في المستودع المحلي بعد تسليم presets.
- بعد Hard Refresh على النسخة المحدّثة: يجب أن تظهر البطاقات الثلاث فوق المحرر داخل `#module=tools`.

## شاشة العمل اليومية × الأرشيف

| المنطقة | ماذا تعرض |
|---------|-----------|
| **أوامر الصيانة الجاهزة** | جديد / فشل يحتاج إعادة فقط |
| **شاشة العمل اليومية** | فشل تنفيذ المحرر · قيد التنفيذ |
| **سجل التنفيذ / الأرشيف** | الناجح مع التاريخ · المنفّذ · النسخة/الطلب |
| **تنظيف السجل** | ينقل المنجز للأرشيف **بدون حذف** |
| **رقم الطلب المرتبط** | اختياري — عند النجاح يُغلق الطلب وتظهر «تم تنفيذ أمر الصيانة بنجاح بتاريخ…» |

## الملفات

| ملف | دور |
|-----|-----|
| `pages/admin.html` | قسم المساحة + قائمة الأوامر الجاهزة + طابور/أرشيف |
| `assets/js/modules/admin-sql-presets.js` | فهرس الأوامر + تقسيم السكربت + حالة مُنفذ/فشل |
| `assets/js/modules/admin-sql-workspace.js` | تشغيل / طابور / أرشيف / تنظيف السجل (مع كتالوج احتياطي إن فشل تحميل الوحدة) |
| `assets/css/admin-sql-workspace.css` | تنسيق |
| `supabase/sql/COPY-ME-admin-sql-workspace.sql` | RPC الأساس + فحص حرفي للفاصلة المنقوطة داخل `$$` |

## كيف تشغّل إصلاحًا؟

1. Hard Refresh لـ `/pages/admin.html` (أو النسخة المنشورة بعد دمج التحديث)
2. سجّل دخول الإدارة → **⚙ أدوات الصيانة** (`#module=tools`)
3. تحت **أوامر الصيانة الجاهزة** اختر البطاقة (مثل «إصلاح دخول المندوب بعد القبول») → **تشغيل** → أكّد
4. عند النجاح: تختفي من الشاشة اليومية وتظهر في **سجل التنفيذ / الأرشيف**
