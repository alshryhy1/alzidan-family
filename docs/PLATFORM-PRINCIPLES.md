## قواعد دستورية حاسمة (قبل أي تنفيذ)

### قاعدة أ — تحديد الطبقة قبل أي شاشة/ميزة

> لا يجوز إنشاء أي شاشة أو نموذج أو ميزة قبل تحديد طبقتها في معمارية المنصة.

أي فكرة جديدة تُسأل أولًا:

1. هل هي **Product Language**؟
2. أم **Request Experience**؟
3. أم **Validation Engine**؟
4. أم **Workflow**؟
5. أم **Tree Engine** (كتابة `tree_children` فقط)؟
6. أم **Delegate Workspace**؟
7. أم **Admin UX** / **Health Center** / **SQL Workspace**؟
8. أم **Family Engine** / **Data Integrity**؟

إن تعذّر وضعها في طبقة واحدة واضحة → **لا يبدأ تنفيذها**.
### قاعدة ب — لغة المستخدم أولًا (تكمّل No Database Thinking)

> كل واجهة تُصمم بلغة المستخدم أولًا، ثم تُربط بالمحرك، ولا تُبنى مباشرة فوق قاعدة البيانات.

### قاعدة ج — Truth Before Speed (الصحة قبل السرعة)

> صحة البيانات وجودة الشجرة أهم من سرعة الاعتماد. كل الفحوصات اللازمة تُنفَّذ قبل أي طفرة على الشجرة.

بعد اعتماد هذه القواعد: **لا تطوير خارج المسار الكانوني** — أي فكرة تُسأل أولًا: «في أي مرحلة/طبقة؟»

## المبادئ

### 1) Human First

كل ما يراه المستخدم فعل بشري. التفاصيل: [`PRODUCT-LANGUAGE.md`](./PRODUCT-LANGUAGE.md).

### 2) No Database Thinking

أي شاشة جديدة تُراجع بالسؤال:

> هل تجعل المستخدم يفكر مثل قاعدة البيانات؟

إن نعم → تُعاد صياغتها. ممنوع في الواجهة: حقول/مفردات مثل Parent · branch_key · request_id كعنوان · tree_card · JSON.

تُكمَّل بـ**قاعدة ب** أعلاه: التصميم بلغة المستخدم أولًا → ثم الربط بالمحرك — لا بناء فوق الجداول.

### 3) الطلب = جلسة عمل

الطلب ليس معاملة ورقية فقط — هو **سياق عمل** يجمع النية والأدوات والحالة والمالك حتى الإغلاق.

### 4) الطلبات محور العمل

الزائر يبدأ نية → **Validation Engine** يفحص الحقائق → **Workflow Engine** يدير الجلسة → المندوب ينجز → الإدارة تراقب التدفق. لا مسارات عمل موازية تتجاهل الطلب.

### 5) واجهة واحدة لكل دور

| الدور | واجهة | سؤال محوري |
|-------|--------|------------|
| زائر | Request Experience / البوابة | ماذا تريد أن تفعل؟ |
| مندوب | Delegate Workspace | ماذا يجب أن أنجز الآن؟ |
| إدارة | Admin UX | أين التدفق؟ أين الاختناق؟ |

لا تُخلط أدوات الإدارة داخل مساحة المندوب، ولا منطق المندوب داخل لوحة المراقبة.

### 6) الحقائق تُقدَّم — النظام يتحقق ويربط

الزائر والمندوب والإدارة **لا يبنون الشجرة**. يقدّمون حقائق؛ النظام يتحقق (Validation Engine) ويربط ويقرّر قابلية التطبيق؛ Workflow يدير الحالة؛ Family Engine يكتب عند الاعتماد المتحقَّق فقط.

### 7) Workflow = مصدر الحقيقة لحالة الطلب

حالة الطلب وانتقالاتها وملكيتها اللحظية تُقرأ وتُكتب عبر **Workflow Engine** فقط (ADR-010). الواجهات تستدعي المحرك — لا تخزّن حالة موازية.

### 8) Validation Engine يتحقق ولا ينفّذ

محرك التحقق مرحلة مستقلة ([`VALIDATION-ENGINE.md`](./VALIDATION-ENGINE.md)): يكتشف الأخطاء والتعارضات **قبل** وصول الطلب للمندوب أو طفرة الشجرة. لا يكتب على الشجرة — يُرجع نتيجة تحقق واضحة (قبول للمسار / رفض / طلب تصحيح) مع أسباب للمندوب.

### 9) لا كتابة مباشرة للخدمات في العمليات المعتمدة على طلب

عمليات الفهرس ([`REQUEST-CATALOG.md`](./REQUEST-CATALOG.md)) لا تكتب على Family Engine / Memory / Cards من الواجهة مباشرة لتجاوز المحرك.  
المسار: نية → تحقق → انتقال Workflow → تطبيق الخدمة عند `applied`.

### 10) قاعدة الثلاث لغات

تقني · نظام · مستخدم — جدول حي في [`PRODUCT-LANGUAGE.md`](./PRODUCT-LANGUAGE.md).

### 11) الخدمات لا تعرف الواجهة

Business Services / Family Engine لا تستورد شكل الشاشة ولا أسماء الأزرار. تعرف عقود بيانات وصلاحيات استدعاء من المحرك.

### 12) الصلاحيات ليست بإخفاء الأزرار فقط

إخفاء زر ≠ أمان. الفرض في **Delegates v2** (RPC / محرك) إلزامي. الواجهة تعكس الصلاحية؛ لا تكون مصدرها الوحيد.

## Single Source of Truth (SSOT)

كل معلومة لها **مصدر واحد** فقط. ممنوع أن تخزّن شاشة أو تفسّر نفس المعلومة بطريقة ثانية.

| المعلومة | المصدر الوحيد |
|----------|----------------|
| نتيجة التحقق · التعارضات · أسباب الرفض/التصحيح | **Validation Engine** |
| حالة الطلب · الانتقال · المالك اللحظي | **Workflow Engine** |
| صلاحية المندوب (دور · فرع · عمليات · تفعيل) | **Delegates v2** |
| بيانات الشخص / الشجرة | **Family Engine** |
| الأخبار / المناسبات المعتمدة كأحداث مجال | **Events** (عبر المسار المعتمد + Event Bus حيث ينطبق) |
| الذكريات | **Memory** |

عرض الواجهة = قراءة من المصدر — ليس نسخة محلّية تُصبح حقيقة بديلة.

## Zero Duplicate Logic

أي منطق لا يُكتب مرتين.

إذا احتاج الزائر والمندوب والإدارة التحقق من الشيء نفسه → يُكتب **مرة واحدة** داخل **Validation Engine** أو المحرك أو الخدمة، وتستدعيه الواجهات.

ممنوع نسخ قواعد الاعتماد / التعيين / التحقق في JavaScript لكل صفحة.

يرتبط بـ ADR-005 (محرك شجرة واحد) ويوسّعه لكل منطق طلبات وصلاحيات وتحقق.

## Family Engine Alignment + Single Write Rule

المرحلة الكانونية في الخارطة = **مواءمة** لا إعادة كتابة:

- توحيد نقطة الدخول للعمليات المعتمدة على طلب  
- منع الكتابة خارج Workflow لتلك العمليات  
- تحويل الشجرة/المناسبات/الذكريات/البطاقات/التصويت/الأخبار إلى **خدمات واضحة**  
- إزالة التكرار بين مسارات الإدارة والمندوب والزائر  

### قاعدة الكتابة الواحدة (Single Write Rule)

> لا كتابة مباشرة على الشجرة من الواجهة. كل إضافة/تعديل على بيانات الشجرة يمر عبر **Workflow Engine** + **Validation Engine** فقط.

الخدمات موجودة؛ المطلوب عقود وحدود — لا مشروع «إعادة بناء الشجرة».

### إضافة دستورية — Tree Engine الكاتب الوحيد لـ `tree_children` (2026-08-09)

> **لا يجوز لأي جزء من النظام أن يكتب مباشرة في `tree_children`.**  
> أي تعديل: **Validation → Workflow → Tree Engine** فقط.  
> **Tree Engine = المسؤول الوحيد عن الكتابة.**

هذه إضافة صريحة لـ Single Write Rule (وليست استبدالًا لها). طبقة Family Engine Alignment تُكمّل المواءمة؛ Tree Engine هو منفذ الكتابة الوحيد المسموح لجدول الأبناء.

**خريطة الملكيات (لا «أصلح كل شيء في SQL»):**

| نوع المشكلة | أين تُحل |
|-------------|---------|
| بيانات قديمة سيئة (مثل `parent = NULL`) | **Data Integrity** (كشف) + **SQL Workspace** (إصلاح يدوي بعد موافقة · أرشفة بعد الإغلاق) |
| منع التكرار مستقبلًا | **Validation Engine** + **Workflow** — كل مسار كتابة إلى `tree_children` يرفض `parent=NULL` عبر Tree Engine |
| منع وصول المستخدم للخطأ | **Request Experience** — لا طلب إن كان الشخص موجودًا / الأب خطأ / البيانات ناقصة |
| مراقبة مستمرة | **Health Center** (قراءة فقط — R-7) |

**سلسلة الطبقات:**

```
User → Request Experience → Validation Engine → Workflow Engine
     → Tree Engine (الكاتب الوحيد لـ tree_children)
     → Data Integrity (مراقبة)
     → SQL Workspace (إصلاح legacy فقط · بلا auto-run من Health)
```

**صدق الحالة اليوم (دين — لا ندّعي اكتمال الفرض):** الوحدة `assets/js/modules/tree-engine.js` (`AlzidanTreeEngine`) موجودة كحارس/مُطبّع صفوف (ترفض `parent=NULL` وتوحّد `parent`/`parent_name`). مسارات متعددة ما زالت تستدعي RPC/استيرادًا مباشرة — **دين مواءمة** تحت Tree Engine، موثّق في [`PATCH-1-WRITE-PATHS.md`](./PATCH-1-WRITE-PATHS.md):

| نقطة كتابة معروفة (دين) | ملاحظة |
|---------------------------|--------|
| `delegate.js` → `tree_children_insert_v1` / update / delete | مسار مندوب مباشر — حارس parent مضاف؛ الهدف: تمرير عبر Tree Engine فقط |
| `admin-family-mgmt.js` / إدارة الشجرة | كتابة إدارية موازية |
| `request-actions.js` → `admin_tree_children_import_v1` | اعتماد بطاقة — يستدعي `prepareChildWriteRow` قبل RPC |
| `admin_tree_children_import_v1` / `admin_tree_child_upsert_v1` (SQL) | مسارات خادم — لم تُغلف بالكامل بعد |
| استيراد جماعي / صيانة SQL Workspace | إصلاح legacy فقط — ليس مسار منتج يومي |

المطلوب لاحقًا (Family Engine Alignment / Tree Engine v2): نقل كل النداءات أعلاه إلى واجهة Tree Engine واحدة؛ Validation ترفض قبل الوصول؛ Workflow لا يطلق كتابة بلا نتيجة تحقق.

## بوابة سريعة قبل أي تصميم/كود

0. **أي طبقة؟** (قاعدة أ — بما فيها Validation Engine و**Tree Engine** للكتابة على `tree_children`) — إن لم تُجب → لا تنفيذ.  
1. هل تخالف Human First أو No Database Thinking أو **قاعدة ب** أو **Truth Before Speed**؟ → أعد الصياغة.  
2. هل نية جديدة بلا صف في Request Catalog؟ → أضف الصف أولًا.  
3. هل فحص حقائق/تعارض/اكتمال قبل الشجرة؟ → **Validation Engine** فقط.  
4. هل تغيّر حالة طلب؟ → Workflow فقط.  
5. هل كتابة `tree_children`؟ → **Tree Engine فقط** (بعد Validation + Workflow) — ممنوع INSERT/RPC مباشر من UI.  
6. هل صلاحية؟ → Delegates فقط.  
7. هل تكرر منطقًا موجودًا في صفحة أخرى؟ → انقله للمحرك/الخدمة (Zero Duplicate Logic).  
8. هل تخزّن حقيقة لها مصدر آخر؟ → SSOT — اقرأ من المصدر.  
9. هل القفز يتجاوز البوابتين (Delegates قبول · تجميد الدستور الحي) أو سلّم المراحل؟ → راجع [`ENGINEERING-ROADMAP.md`](./ENGINEERING-ROADMAP.md).  
10. هل بيانات legacy فاسدة؟ → Health Center للكشف · SQL Workspace للإصلاح اليدوي — **لا** إصلاح تلقائي من الواجهة.
